---

ClipSync 安静地待在托盘里。两台设备用一个 4 位配对码互认一次——不需要账号、
不需要服务器、不用填 IP——此后你复制的东西就会出现在另一台上。流量端到端加密，
在你的设备之间直接传输，不经过任何第三方。

可以理解成**能在 Windows 和 macOS 之间用的「隔空剪贴板」**——不需要 Apple ID，
不需要任何账号，中间也没有云服务。

> [!NOTE]
> 界面支持中文与英文，默认跟随系统语言，也可在「高级设置 › 语言」里随时切换，
> 改完立即生效无需重启。日志保持中文——它是诊断输出而非界面文案，统一一种
> 语言才好比对不同用户报上来的问题。

## 什么场景用得上

**你同时用一台 Mac 和一台 PC。** 这正是苹果「通用剪贴板」完全不管的情况：只要
有一台是 Windows，那套东西就用不了。复制一段网址、一段文字、一张截图或一个
压缩包，在另一台直接粘贴。

**你总在给自己发文件。** 用微信/QQ 文件传输助手在自己两台电脑之间倒腾文件当然
可行，但数据要上传到别人的服务器，要点好几下，图片还会被压缩。复制 → 粘贴更快，
而且字节从不离开你的机器。

**你要从远程桌面里往外复制东西。** 通过屏幕共享或远程桌面干活时，经常想把一条
命令、一段日志、一个 token 弄到本地。ClipSync 独立于远程会话运行，所以即使那个
会话自己的剪贴板互通不好使，它照样能用——而且 macOS 上传输被声明为后台流量，
传大文件不会把你正盯着的屏幕共享画面拖卡。

**公司不让用云同步。** 没有服务端、没有账号、没有遥测。流量在你自己的局域网或
你自己的 VPN 里直连，不会越过你已有的网络边界。

**你有两台以上机器。** 台式、笔记本、工作机可以组成一个组，不必两两配对——设备
之间会互相引荐，其中任意一台离线都不影响其余的。

**你要传的不只是文字。** 在资源管理器或访达里复制文件，到另一台直接粘贴，传的
是真正的文件——支持断点续传、完整性校验，除了你自己设的上限之外没有大小限制。

## 特性

- **配对之后零配置。** 一个 4 位码建立永久互信。没有账号，没有云服务，
  没有需要手工编辑的配置文件。
- **文本、图片、文件。** 大文件分块传输并支持断点续传；超过设定大小的文件
  会挂起等你点「取回」，而不是自动下载。
- **端到端加密。** Noise 协议（`Noise_IK`），每台设备一对静态密钥。配对用
  SPAKE2，那 4 位数字**从不上线**。
- **自己找最优路径。** 优先同网段直连，其次覆盖网，最后公网。**不绑定任何
  组网产品**：直接枚举本机网卡，所以 Tailscale、ZeroTier、NetBird、Nebula、
  WireGuard 乃至公网端口转发全都开箱可用，无需适配。
- **不打扰你。** 空闲内存约 11 MB、CPU 约 0.03%，二进制 1.4 MB，只有一个托盘
  图标。macOS 上文件传输被声明为后台流量，会主动给屏幕共享和视频通话让路。
- **尊重敏感内容。** 密码管理器等标记为机密的剪贴板内容自动跳过。
- **中英双语界面。** 默认跟随系统语言，也可在托盘里随时切换，无需重启。

## 与其它做法的对比

| | Windows ↔ macOS | 数据不出本机 | 自动 | 支持文件 |
|---|:---:|:---:|:---:|:---:|
| **ClipSync** | ✅ | ✅ | ✅ | ✅ |
| 苹果通用剪贴板 | ❌ 仅限苹果设备 | ✅ | ✅ | ✅ |
| 给自己发消息（微信/QQ/TG） | ✅ | ❌ 经他们的服务器 | ❌ 手动 | ✅ |
| 云剪贴板类工具 | ✅ | ❌ 经他们的服务器 | ✅ | 看具体产品 |
| Windows 云剪贴板 | ❌ 仅限 Windows | ❌ 经微软 | ✅ | ❌ 仅文本 |
| KDE Connect | ⚠️ 主要面向 Linux/Android | ✅ | ✅ | ✅ |
| 远程桌面 / VNC 的剪贴板 | ✅ | ✅ | ⚠️ 依赖会话 | ⚠️ 受限 |
| 共享文件夹 / U 盘 | ✅ | ✅ | ❌ 手动 | ✅ |

ClipSync 的位置是这几条的**组合**：跨平台、点对点、自动、能传文件，而且不用注册
任何东西。

它**刻意不做**剪贴板历史管理器——没有那种记录你复制过的一切的可搜索档案，只同步
当前剪贴板，仅此而已。想要历史记录的话，配一个本地的历史工具即可，两者不冲突。

## 安装

### 下载发布版

到 [Releases](https://github.com/doujianghub/clipsync/releases/latest) 取对应
平台的构建：

| 平台 | 文件 |
|---|---|
| macOS（Apple Silicon + Intel） | `ClipSync-<版本>-macos-universal.zip` |
| Windows（x64） | `ClipSync-<版本>-windows-x64.zip` |

**macOS**：把 `ClipSync.app` 拖进「应用程序」。由于发布版只有 ad-hoc 签名而非
付费的 Developer ID 证书，首次打开会被系统拦下：**右键点图标 → 打开**（双击
不给放行按钮）。macOS 15 及以上改去「系统设置 › 隐私与安全性」点「仍要打开」。
若提示「已损坏」或「无法打开」，多半是传输弄坏了签名，执行
`xattr -cr /Applications/ClipSync.app` 即可。

**Windows**：解压到任意位置，运行 `clipsync.exe`。同样的原因，SmartScreen 首次
可能拦截，选「更多信息 → 仍要运行」。

### 从源码构建

需要 Rust 1.88 或更高版本。

```bash
git clone https://github.com/doujianghub/clipsync
cd clipsync
cargo build --release
```

产物在 `target/release/clipsync`。**务必用 release 构建**——debug 下加密与哈希
慢一个数量级，同一个传输要慢约 25 倍。

打包成 macOS 的 `.app`：

```bash
scripts/package-macos.sh                    # 仅本机架构
scripts/package-macos.sh --universal        # Intel + Apple Silicon 通用二进制
scripts/package-macos.sh --universal --dmg  # 再打一个 dmg 便于分发
```

## 快速上手

1. 两台机器都启动 ClipSync，托盘出现图标。
2. A 机：托盘菜单 → **显示配对码…**，弹出 4 位数字并带实时倒计时。
3. B 机：托盘菜单 → **输入配对码…**，敲那四位。
4. 完成。在任意一台上复制点什么试试。

**全程不碰命令行、不输 IP**——B 会自己找到 A。配对码 3 分钟有效，只配一台设备，
配对成功即失效。

> **为什么只有 4 位？** 这个码只能靠人念、人敲——用剪贴板把它递过去是循环依赖，
> 而剪贴板还没打通正是本工具要解决的问题。1 万种组合看着不多，撑住它的是
> **每会话 5 次猜测上限**：SPAKE2 让离线穷举不可能，而在线穷举实测有 818 次/秒，
> 没有上限的话十几秒就能跑完 1 万种。有了上限，单会话被猜中的概率是 5/10000，
> 且与有效期多长无关。
>
> 期间关掉配对码窗口不影响监听——会话只在超时、成功、或连错 5 次时结束。

### 三台以上

不必两两都配。已连接的设备会**互相引荐**——A 分别与 B、C 配对后，B 和 C 会通过
A 认识彼此并直连，此后 **A 关机也不影响** B 与 C 同步。谁当引入者都行。

> 引荐意味着信任是传递的：你信任 B，B 信任 C，你就自动信任了 C。所以设备列表里
> 会标出「经 某某 认识」，让你分得清哪些是自己亲手加的。
>
> 既然这些设备构成的是一个**组**，退出也按组来：点某台设备是把它移出组，组里
> 所有成员一起移除，它自己也会清空配对；点「退出设备组」则是本机离开。两者都
> 可逆——重新配对一次即可回来。

## 托盘

日常用得到的都在第一层：

```
ClipSync — 已连接 1 / 2 台
──────────────
显示配对码…            换个配对码             输入配对码…
已配对设备 ▸
☑ 同步图片             ☑ 同步文件             ☐ 暂停同步
☐ 开机自启             高级设置 ▸             退出
```

配对会话进行中时，第一项会变成实时倒计时（`配对码 1234 · 剩 2:47`）——弹窗是
系统原生模态窗，显示出来文字就定死了，能动的只有菜单。

有文件等着取回时，菜单最上方会多出一行 `取回 报告.zip 等 3 个（4.2 GB）`，
托盘图标右上角同时点一个蓝点。没有待取项时这一行不存在。

自动取回上限、发送限速、同步端口、传输前压缩、日志开关收在「高级设置」里——
少数人偶尔要用，不必每天都看见。标签上直接写着当前值（`自动取回：100 MiB…`），
点一下弹出常用档让你**点选**；档位不合用就选「自定义…」，接受 `500MB`、
`1.5GiB`、`20mbps` 这类写法。

图标颜色即状态：绿=已连接、灰=未连接、琥珀=已暂停、红=同步已停止。
传大文件时图标会**轻微脉冲**（淡下去再回来），颜色仍表示连接状态，互不干扰。

## 命令行

日常完全用不到，托盘覆盖了所有操作。这些是给脚本和排查用的：

```bash
clipsync                       # 后台同步 + 托盘（默认）
clipsync pair --host           # 主持配对，显示一次性配对码
clipsync pair <配对码>          # 加入配对，自动找到对方
clipsync pair <对方IP> <配对码> # 自动发现全落空时的手动出口
clipsync list                  # 列出已配对设备及其已知地址
clipsync addrs                 # 显示本机可达地址及类型
clipsync clipdiag              # 诊断剪贴板与权限问题
clipsync autostart [on|off]    # 查询/设置开机自启
```

## 配置

配置在配置目录下的 `settings.json`，所有项都能在托盘菜单里改，一般不必手工编辑。

| 键 | 默认 | 说明 |
|---|---|---|
| `listen_port` | `47684` | 同步连接监听端口 |
| `auto_fetch_bytes` | 100 MiB | **收到**的文件多大以内自动拉取；超过则挂起等你在托盘点「取回」。不影响发送，也不管文本/图片 |
| `allow_image` / `allow_files` | `true` | 类型开关（收发都受约束） |
| `file_cache_bytes` | 1 GiB | 续传缓存上限，超出按最久未使用淘汰 |
| `upload_limit_bytes_per_sec` | `0` | 文件发送限速，`0` = 不限速 |
| `compress_transfers` | `true` | 传输前自适应压缩 |
| `verbose_log` | `false` | 记录 debug 级详细日志 |

配置目录：

- **Windows** —— `%APPDATA%\ClipSync\`
- **macOS** —— `~/Library/Application Support/ClipSync/`

配置损坏不会导致程序打不开：坏文件会被另存为 `.bad` 并回退到默认值，日志里有记录。

### 环境变量

| 变量 | 用途 |
|---|---|
| `CLIPSYNC_LOG` | 日志级别，如 `debug` |
| `CLIPSYNC_CONFIG_DIR` | 自定义配置目录（便于一机多实例测试） |
| `CLIPSYNC_PEERS` | 手动补充对端地址（`ip:port` 逗号分隔），用于自动发现覆盖不到的场景 |
| `CLIPSYNC_NO_WATCH` | 禁用本地剪贴板监听，作为纯接收设备 |
| `CLIPSYNC_NO_TRAY` | 禁用托盘，纯后台运行 |
| `CLIPSYNC_DEVICE_NAME` | 自定义本机设备名 |

## 工作原理

### 怎么找到对方

地址有三个通用来源，代码里没有任何一处认识"Tailscale"这个词：

1. **配对时交换** —— 配对完成即互知对方全部地址（含各类虚拟网卡）。
2. **局域网组播信标** —— 同网段设备周期性宣告，IP 变了也能跟上。
3. **加密通道内互告** —— 已连接的双方持续同步各自地址；只要还有任意一条路径通，
   其它路径的地址就能学到。

候选地址按拓扑距离排序：同网段直连 → 覆盖网/VPN → 公网。用 `clipsync addrs`
可查看本机被识别到的地址。

> **为什么信标是明文且不认证的？** 因为它只负责"提示地址"，认证始终由传输层
> 负责——伪造信标至多导致一次失败的连接尝试，`Noise_IK` 握手需要对端的静态
> 私钥才能通过。

### 端口一览

| 端口 | 用途 | 协议 |
|---|---|---|
| 47684 | 同步连接（`listen_port` 可改） | TCP |
| 47685 | 配对（仅 `pair` 期间短暂监听） | TCP |
| 47690 | 设备发现信标 | UDP 组播 |
| 47691 | 配对发现信标（仅 `pair` 期间） | UDP 组播 |

组播组为 `239.255.71.83`（管理范围地址，不会跨路由器外泄）。

### 文件同步

剪贴板是**「最新值获胜」**的语义，不是队列。文件同步的设计完全围绕这一点：

**复制文件时只发清单，不发内容。** 清单很小（文件名/大小/标识），对端立刻知道
有什么，并回答「我需要哪几段」，真正的字节才开始搬运。

**传输中复制了别的内容 → 立即取代。**

| 做法 | 后果 |
|---|---|
| 等旧传输完成 | 你现在要用的新内容被大文件卡住，体验灾难 |
| 传完旧的再说 | 对端剪贴板变成旧文件，与你本机不一致，更糟 |
| **立即取代**（本方案） | 对端剪贴板始终与你一致；已收字节留作续传 |

**再次复制同一文件 → 自动续传或秒同步。** 缓存完整则零传输；只有前 N 字节则
只索取剩下的；文件被改过（标识随大小与修改时间变化）则缓存失效重传。

**不吃内存、不产生损坏文件。** 全程流式分块（256 KB），传 90 MB 文件内存恒定
约 13 MB；完成时校验内容哈希，源文件若在传输中被改动会被发现并重传。

**自适应压缩。** 发送前取文件开头试压，压得动才压——文本/代码/日志类等效吞吐
提升约 40%；jpg/mp4/zip 等已压缩内容自动跳过，不浪费 CPU。

### 实测性能

release 构建，90 MB 文件走本机回环：

| 场景 | 耗时 | 吞吐 |
|---|---|---|
| 不可压缩文件（随机数据） | 0.61 s | 146 MB/s |
| 可压缩文本（日志类） | 0.49 s | 191 MB/s（等效） |
| 限速 10 MB/s | 8.36 s | 与设定一致 |
| 重复内容（缓存完整命中） | ~1 ms | 零传输 |

图片在帧层压缩后才发送——一张 4K 截图裸 RGBA 是 33 MB，压完通常在 6%–15%
（纯色界面越多压得越狠，照片类噪点多的会自动跳过压缩），在低于千兆的链路上
差别巨大。广播给多台设备时只压一次，各连接共享同一份字节。

## 安全性

- **传输**：`Noise_IK`（Curve25519 + ChaCha20-Poly1305 + BLAKE2s）。每台设备
  一对静态密钥，私钥绝不外传，以 `0600` 权限存放。
- **配对**：SPAKE2 口令认证密钥交换。4 位码从不上线，对抓到的握手做离线穷举
  不可能；在线猜测每会话上限 5 次。
- **认证**：对端由静态公钥识别。未配对的设备无法完成握手，未认证流量在触及
  任何剪贴板数据之前就被拒绝。
- **没有第三方**：没有中继、没有账号体系、没有遥测。数据在你的设备之间直连。

**威胁模型。** ClipSync 保护的是剪贴板内容在**传输途中**不被网络观察者和同网段
未配对设备读取。它**不**防护已被攻陷的终端——任何能在本地读你剪贴板的东西，
同样能读到 ClipSync 同步的内容。

报告漏洞请见 [SECURITY.md](SECURITY.md)。

## 出问题时怎么查

日志写在配置目录的 `logs/clipsync.log`（4 MB 滚动，保留一代）。托盘勾上
「详细日志」即可记录 debug 级细节，**无需重启**，复现一次后再关掉；
「打开日志文件夹」直接定位到该目录。

日志里几条有用的信号：

- 启动时的 `本机地址: …` —— 和对端那一行对照，一眼看出两台是不是同一网段。
- `写入剪贴板耗时 … ms` —— 只在超过 200 ms 时才记，所以它出现就说明本地编解码
  是瓶颈。
- `系统拒绝读取 …` —— macOS 挡住了文件访问，消息里直接写明该去系统设置的哪一页。
  `clipsync clipdiag` 会逐条列出每个路径的判定。

**所有设备必须运行同一协议版本。** 1.0.0 改动了线缆格式，与旧版本混用会导致
反复重连。

## 已知限制

- **日志只有中文。** 界面已完整双语，但日志没有。这是有意的：日志是诊断用的，
  统一一种语言才好比对不同用户报上来的问题。如果这影响到你，欢迎提 issue。
- **不支持 Linux。** 代码能编译，但剪贴板变化检测、弹窗、开机自启全是空实现——
  是不可用，而不只是功能降级。
- **Windows 侧目视验证不完整。** 弹窗的 DPI 与字体处理、部分较新的托盘项在
  macOS 上验证过，未在 Windows 实机确认。
- **密码管理器行为是模拟测试的。** 敏感内容检测遵循平台的既定约定，但某个具体
  的密码管理器是否真的遵守，没有用真实软件验证过。
- **承诺文件**（`com.apple.pasteboard.promised-file-url`）能被 `clipdiag` 识别
  并解释，但尚未实现传输。
